#+TITLE: org-apple-reminders Setup
#+STARTUP: overview

Loads and configures the [[https://github.com/deno1011/org-apple-reminders][org-apple-reminders]] package for bidirectional
sync between org-mode and Apple Reminders.

macOS only (JXA/osascript required).

#+begin_src emacs-lisp :tangle yes
;;; 55-apple-reminders.el --- Apple Reminders bridge -*- lexical-binding: t; -*-

(defvar my/data-dir)
(defvar org-apple-reminders-sync-file)
(defvar org-apple-reminders-auto-sync-interval)
(defvar org-apple-reminders-included-lists)

(declare-function org-apple-reminders-setup "org-apple-reminders")
#+end_src

* Installation and auto-update

Installs =org-apple-reminders= from GitHub via =package-vc-install= (Emacs 29+).
After installation, schedules a silent background update check 10 seconds after
Emacs becomes idle — so the package is always at the latest =main= commit on the
next startup, without slowing down init.

Once the package is available on MELPA, replace this block with =:ensure t= in
the use-package form below.

Elpaca clones from GitHub directly (no MELPA dependency), generates
autoloads, and handles updates via =M-x elpaca-fetch-all=. No more
"Overwrite previous checkout?" prompts; no `cl-letf` workarounds;
no async background `git pull` race.

* Configuration

Configures the package as recommended in the README:

- =org-apple-reminders-sync-file= :: The org file mirrored with Apple Reminders.
  Created automatically on first sync.
- =org-apple-reminders-auto-sync-interval= :: Seconds between background pulls
  (default: 300 = 5 minutes).
- =org-apple-reminders-setup= :: Starts the timer, registers org-agenda and
  org-capture, and binds the =C-c r= command map. Must be called once.

The package binds its own keymap under =C-c r= (=C-c r R= sync, =C-c r p= /
=C-c r m= push heading or region, =C-c r d= remove from Apple, =C-c r D=
delete, …), so no manual =global-set-key= calls are needed.

#+begin_src emacs-lisp :tangle yes
;; HARD GATE on data-dir.el — wrap the ENTIRE use-package, not just setup.
;;
;; Race condition this guards against: on a fresh install bootstrap hasn't
;; written `data-dir.el' yet when this module loads. `my/data-dir' is still
;; init.el's `~/emacs/' fallback (NOT the BW.Repo-derived path). If we let
;; use-package run:
;;   1. :ensure installs the package via elpaca.
;;   2. :config's `(setq org-apple-reminders-sync-file ...)' BAKES the path
;;      to `~/emacs/data/org/reminders.org' (wrong root) — that variable is
;;      now permanently misconfigured for this Emacs session.
;;   3. Even if we gate `(org-apple-reminders-setup)' itself, the baked
;;      sync-file is what any subsequent sync command, idle timer, or
;;      hook will write to — and writes there will trip
;;      `git-auto-commit-mode' with "Schwerwiegend: Kein Git-Repository".
;;   4. The bootstrap THEN writes data-dir.el → ~/emacs14/ later in the
;;      same session, but org-apple-reminders-sync-file is already wrong.
;;
;; Gating the whole use-package means: on first install nothing loads, no
;; setq runs, no sync-file is baked at the wrong path. After bootstrap
;; writes data-dir.el and the user restarts, elpaca installs the package
;; on that second start (modest one-time delay) with `my/data-dir' already
;; pointing at the correct folder. GTD works without this gate only
;; because the bootstrap's own `generate-starter-data' uses a let-bound
;; `target' rather than the captured `my/data-dir' — the asymmetry that
;; made reminders end up in ~/emacs/ while inbox.org landed in ~/emacs14/.
(when (and (eq system-type 'darwin)
           (file-exists-p
            (expand-file-name "data-dir.el" user-emacs-directory)))
  (use-package org-apple-reminders
    :ensure (org-apple-reminders
             :host github
             :repo "deno1011/org-apple-reminders"
             :branch "main")
    :config
    (setq org-apple-reminders-sync-file
          (expand-file-name "data/org/reminders.org" my/data-dir))

    ;; nil = sync all Apple Reminders lists (the default — not restricted).
    ;; Set to a list of names to restrict, or pick interactively with `C-c r i'.
    (setq org-apple-reminders-included-lists nil)

    ;; New unlinked TODOs in known reminder files use the nearest level-1
    ;; heading as the Apple list name. TODOs outside a list section use the
    ;; configured/default Apple Reminders list.

    (org-apple-reminders-setup)))
#+end_src
