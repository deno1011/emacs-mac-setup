#+TITLE: messenger-bridge — channel-agnostic messaging
#+STARTUP: overview

Installs [[https://github.com/deno1011/emacs-messenger-bridge][emacs-messenger-bridge]] — a generic, channel-agnostic message
bridge so Emacs (and the agent in =60_emacs-agent-runtime=) can send messages
through an external channel adapter (WhatsApp, Telegram, …) via a plain
directory of JSON files. The bridge knows nothing about any specific messenger;
concrete adapters are separate processes.

The Emacs side here is generic. The concrete *channel* (e.g. the WhatsApp
adapter) is a separate process — see "WhatsApp adapter" below.

* Install and start

Cloned from GitHub via elpaca. This module loads the bridge for outbound
=messenger-send= support, but does not auto-start its legacy inbound watcher by
default. The EAR scheduler job =messenger.bridge.listener= owns inbound polling
so there is only one consumer of =messenger-bridge-directory=/=inbox=.

If you explicitly want the legacy watcher instead of EAR, set
=my/messenger-autostart= to non-nil before this module loads.

- =messenger-send CHAT TEXT &optional CHANNEL META= — queue an outbound message.
- =messenger-on-message-functions= — abnormal hook, one arg = inbound message
  plist =(:id :channel :chat :text :timestamp :meta)=. Do not use this in
  parallel with the EAR scheduler listener on the same inbox.

#+begin_src emacs-lisp :tangle yes
;;; 65_messenger.el --- channel-agnostic message bridge -*- lexical-binding: t; -*-

(require 'subr-x)
(require 'json)

(declare-function messenger-bridge-start "messenger-bridge")
(declare-function messenger-bridge-stop "messenger-bridge")
(declare-function messenger-send "messenger-bridge")
(defvar messenger-bridge-directory)

(defvar my/messenger-autostart nil
  "When non-nil, start the legacy messenger bridge inbound watcher on load.

Keep this nil when the EAR scheduler job `messenger.bridge.listener' owns
inbound polling for the same bridge directory.")

(when (not noninteractive)
  (use-package messenger-bridge
    :ensure (messenger-bridge
             :host github
             :repo "deno1011/emacs-messenger-bridge"
             :branch "main"
             :depth nil)
    :demand t
    :commands (messenger-send messenger-bridge-start messenger-bridge-stop)
    :config
    ;; messenger-bridge-directory defaults to ~/.emacs.d/messenger-bridge/.
    ;; The WhatsApp adapter's MESSENGER_BRIDGE_DIR must point at the same path.
    (when my/messenger-autostart
      (messenger-bridge-start))))
#+end_src

** WhatsApp adapter launchd service (from Emacs)

=M-x my/whatsapp-adapter-install-service= writes the launchd plist with the
right node binary + adapter path and (re)loads it, so the adapter runs in the
background after login. It refuses until the adapter is cloned and QR-linked
(=auth/= present) — do the one-time =node index.js= QR scan first. The doctor's
"linked" step points here. This keeps the mechanism in the config (reproducible
on a reinstall) while the interactive QR stays a manual step.

(defun my/whatsapp-adapter--status-file (channel)
  "Return the runtime status JSON path for WhatsApp CHANNEL."
  (expand-file-name
   (format "messenger-bridge/status/%s.json" channel)
   user-emacs-directory))

(defun my/whatsapp-adapter--runtime-status (channel)
  "Return the adapter runtime status alist for CHANNEL, or nil."
  (let ((file (my/whatsapp-adapter--status-file channel)))
    (when (file-readable-p file)
      (cond
       ((fboundp 'json-parse-file)
        (json-parse-file file :object-type 'alist :array-type 'list
                         :null-object nil :false-object nil))
       ((fboundp 'json-read-file)
        (let ((json-object-type 'alist)
              (json-array-type 'list)
              (json-false nil)
              (json-null nil))
          (json-read-file file)))))))

(defun my/messenger--link-term (name dir command)
  "Run COMMAND in DIR inside an ansi-term buffer NAME so a login QR renders
in Emacs.  Prepends the detected node bin dir to PATH (Homebrew node is
keg-only and not on the login PATH), so node/npm resolve."
  (let ((dir (expand-file-name dir)))
    (unless (file-directory-p dir)
      (user-error "Adapter not installed: %s — clone it first" dir))
    (require 'term)
    (let* ((default-directory (file-name-as-directory dir))
           (shell (or (getenv "SHELL") "/bin/zsh"))
           (nodebin (let ((n (or (executable-find "node")
                                  (seq-find #'file-executable-p
                                            '("/opt/homebrew/opt/node/bin/node"
                                              "/opt/homebrew/bin/node"
                                              "/usr/local/bin/node")))))
                      (and n (directory-file-name (file-name-directory n)))))
           (full (format "%scd %s && %s"
                         (if nodebin
                             (format "export PATH=%s:$PATH; "
                                     (shell-quote-argument nodebin))
                           "")
                         (shell-quote-argument dir) command))
           (bufname (format "*%s*" name)))
      (when (get-buffer bufname)
        (let ((kill-buffer-query-functions nil)) (kill-buffer bufname)))
      (let ((buf (make-term name shell nil "-lc" full)))
        (with-current-buffer buf (term-mode) (term-char-mode))
        (switch-to-buffer buf)
        (message "Scan the QR shown in *%s*; close the buffer when linked" name)
        buf))))

(defun my/whatsapp-adapter--registered-p ()
  "Return non-nil if the WhatsApp adapter auth store is fully registered."
  (let ((creds (expand-file-name "auth/creds.json" my/whatsapp-adapter-dir)))
    (when (file-readable-p creds)
      (with-temp-buffer
        (insert-file-contents creds)
        (goto-char (point-min))
        (re-search-forward "\"registered\"[[:space:]]*:[[:space:]]*true" nil t)))))

(defun my/whatsapp-adapter-archive-auth ()
  "Archive the WhatsApp adapter auth directory before a fresh link attempt."
  (interactive)
  (let ((auth (expand-file-name "auth" my/whatsapp-adapter-dir)))
    (when (file-directory-p auth)
      (rename-file
       auth
       (expand-file-name
        (format "auth-stale-%s" (format-time-string "%Y%m%d-%H%M%S"))
        my/whatsapp-adapter-dir)
       t))
    (make-directory auth t)
    (message "WhatsApp adapter auth archived; fresh auth/ created")))

(defun my/whatsapp-adapter--prepare-fresh-link ()
  "Archive incomplete WhatsApp auth before an interactive link command."
  (let ((creds (expand-file-name "auth/creds.json" my/whatsapp-adapter-dir)))
    (when (and (file-exists-p creds)
               (not (my/whatsapp-adapter--registered-p)))
      (my/whatsapp-adapter-archive-auth))))

(defun my/whatsapp-adapter-link ()
  "Open a terminal buffer running the WhatsApp adapter so its login QR
renders in Emacs.  Scan it in WhatsApp > Linked Devices (use a SECONDARY
number).  Stop the launchd service first if running; delete auth/ to force a
fresh QR when re-linking (an already-linked adapter shows no QR)."
  (interactive)
  (my/whatsapp-adapter--prepare-fresh-link)
  (my/messenger--link-term "whatsapp-link" my/whatsapp-adapter-dir
                           "exec npm start"))

(defun my/whatsapp-adapter-link-debug ()
  "Open the WhatsApp adapter link terminal with verbose Baileys diagnostics."

  (my/whatsapp-adapter--prepare-fresh-link)

   "whatsapp-link-debug" my/whatsapp-adapter-dir

(defun my/whatsapp-adapter--default-phone ()
  "Return the first phone-like JID from the WhatsApp adapter .env file."
  (let ((env-file (expand-file-name ".env" my/whatsapp-adapter-dir))
        (found nil))
    (when (file-readable-p env-file)
      (with-temp-buffer
        (insert-file-contents env-file)
        (goto-char (point-min))
        (when (re-search-forward "^WA_ALLOWED_JIDS=\\([^,\n]+\\)" nil t)
          (setq found
                (replace-regexp-in-string
                 "[^0-9]" "" (match-string 1))))))
    (when (and found (> (length found) 0))
      found)))

(defun my/whatsapp-adapter-link-pairing-code (phone)
  "Open WhatsApp adapter login using a phone-number pairing code.
PHONE must include the country code.  Punctuation and spaces are ignored."
  (interactive
   (list (read-string "WhatsApp phone with country code: "
                      (my/whatsapp-adapter--default-phone))))
  (let ((digits (replace-regexp-in-string "[^0-9]" "" phone)))
    (unless (string-match-p "\\`[0-9]+\\'" digits)
      (user-error "Phone number must contain digits"))
    (my/whatsapp-adapter--prepare-fresh-link)
    (my/messenger--link-term
     "whatsapp-link-pairing" my/whatsapp-adapter-dir
     (format "WA_DEBUG=1 WA_LOG_LEVEL=debug WA_PAIRING_PHONE=%s exec npm start"
             (shell-quote-argument digits)))))

(defun my/whatsapp-adapter--registered-auth-p (auth-dir)
  "Return non-nil when AUTH-DIR contains registered Baileys credentials."
  (let ((creds (expand-file-name "creds.json" auth-dir)))
    (when (file-readable-p creds)
      (with-temp-buffer
        (insert-file-contents creds)
        (goto-char (point-min))
        (re-search-forward "\"registered\"[[:space:]]*:[[:space:]]*true" nil t)))))

(defun my/whatsapp-adapter--usable-auth-p (auth-dir)
  "Return non-nil when AUTH-DIR contains credentials that can reconnect.

Baileys v7/WhatsApp Business can persist `registered=false' even after a
successful Business link.  Treat a saved self identity plus account sync as
usable auth instead of archiving it as half-created QR state."
  (let ((creds (expand-file-name "creds.json" auth-dir)))
    (when (file-readable-p creds)
      (with-temp-buffer
        (insert-file-contents creds)
        (or (progn
              (goto-char (point-min))
              (re-search-forward "\"registered\"[[:space:]]*:[[:space:]]*true" nil t))
            (and (progn
                   (goto-char (point-min))
                   (re-search-forward "\"me\"[[:space:]]*:" nil t))
                 (progn
                   (goto-char (point-min))
                   (re-search-forward "\"lastAccountSyncTimestamp\"[[:space:]]*:" nil t))))))))

(defun my/whatsapp-business-adapter--prepare-fresh-link ()
  "Archive incomplete WhatsApp Business auth before an interactive link command."
  (let* ((auth (expand-file-name "auth-business" my/whatsapp-adapter-dir))
         (creds (expand-file-name "creds.json" auth)))
    (when (and (file-exists-p creds)
               (not (my/whatsapp-adapter--usable-auth-p auth)))
      (rename-file
       auth
       (expand-file-name
        (format "auth-business-stale-%s" (format-time-string "%Y%m%d-%H%M%S"))
        my/whatsapp-adapter-dir)
       t)
      (make-directory auth t)
      (message "WhatsApp Business adapter auth archived; fresh auth-business/ created"))))

(defun my/whatsapp-business-adapter--stop-link-processes ()
  "Stop interactive WhatsApp Business link processes that share auth-business/."
  (dolist (bufname '("*whatsapp-business-link*" "*whatsapp-business-link-debug*"
                     "*whatsapp-business-link-pairing*"))
    (let ((proc (get-buffer-process bufname)))
      (when proc (delete-process proc)))))

(defun my/signal-adapter-uninstall-service ()
  "Unload and remove the Signal adapter launchd service."
  (interactive)
  (let ((plist (expand-file-name
                (format "Library/LaunchAgents/%s.plist"
                        my/signal-adapter--service-label)
                "~")))
    (ignore-errors (call-process "launchctl" nil nil nil "unload" plist))
    (when (file-exists-p plist) (delete-file plist))
    (message "Signal adapter service removed")))
#+end_src

* WhatsApp adapter (separate process)

The WhatsApp channel is [[https://github.com/deno1011/whatsapp-bridge-adapter][whatsapp-bridge-adapter]] — a Node/Baileys process,
*not* an Emacs package (so not installed via elpaca). It links a WhatsApp
number (like WhatsApp Web) and relays messages to/from the bridge's
=inbox/=outbox/=.

The QR scan is interactive (you scan with your phone) and involves a
secondary-number/ToS decision, so it is *not* auto-provisioned. Instead
=M-x my/doctor= walks you through it: it detects how far setup got (not
cloned → npm install → not linked → linked) and prints the exact next command.
The QR step is =M-x my/whatsapp-adapter-link=, which renders it inside Emacs.

⚠️ Unofficial (Baileys) → against WhatsApp ToS, the number can be banned. Use a
*secondary* number.

** One-time setup

#+begin_example
git clone https://github.com/deno1011/whatsapp-bridge-adapter.git
cd whatsapp-bridge-adapter
npm install
cp .env.example .env
#+end_example

Edit =.env=:
- =MESSENGER_BRIDGE_DIR= — MUST equal =messenger-bridge-directory= in Emacs
  (default =~/.emacs.d/messenger-bridge=).
- =WA_ALLOWED_JIDS= — safety whitelist (leave empty for the first run).

** First run + whitelist

Run =M-x my/whatsapp-adapter-link= — it opens a =*whatsapp-link*= buffer
running the adapter (handling the keg-only-node PATH for you) and renders the
QR; scan it in WhatsApp ▸ Linked Devices. (Raw equivalent: =node index.js= in
the adapter dir.)

The =.env= is auto-loaded. With =WA_ALLOWED_JIDS= empty nothing inbound is
relayed; message the linked number (or your "Note to Self") — the adapter logs
the sender JID (incl. the newer =@lid= form) right in that buffer. Put that JID
into =WA_ALLOWED_JIDS= and restart. Now only that chat is relayed, so the agent
talks only to you. The session persists in =./auth= (no QR on later runs).

* Messaging contacts (friends) — with guardrails

Contacts are *channel-agnostic* here. Each ADAPTER fetches its own channel's
contacts and writes them, normalized, to =<bridge>/contacts/<channel>.json= (a
JSON array of ={e164, handle, name}=). The BRIDGE merges every channel's file
on the *E.164 number*, so one name resolves across WhatsApp, Signal, … :

- =M-x messenger-contacts-import= (re)builds the merged table; =(messenger-contacts)=
  returns it (list of plists =(:e164 :name :channels ((CHANNEL . HANDLE) …))=).
- =(messenger-resolve "Mesic")= → the matching record (error if ambiguous).
- =(messenger-contact-handle REC "signal")= → the =(channel . handle)= to send;
  omit the channel for the preferred one (=messenger-contacts-name-precedence=).
- Same E.164 on two channels = ONE record on both; name picked by precedence.
  A channel that hides the number (WhatsApp =@lid=) stays channel-local.

*Honest limitation (per channel):* a freshly linked *WhatsApp* device does NOT
receive your full address book — =contacts/whatsapp.json= fills *incrementally*
from conversations (pushNames) and whatever app-state pushes; do not expect it
complete at first run. *Signal* (signal-cli, linked) DOES expose the linked
account's contacts (number + profile name), so =contacts/signal.json= populates
on connect. For someone not yet in any channel file, address them by number:
=(messenger-send "+E164" TEXT "signal")= or =(... "<num>@s.whatsapp.net" … "whatsapp")=
(after approval).

Outbound is *guardrailed* — because messaging various contacts via the
unofficial client is the #1 WhatsApp ban trigger. =messenger-send= NEVER
prompts (safe for the agent) and refuses unless the recipient is approved:

- *Replies are free:* anyone who has messaged you (seen this session) can be
  replied to without approval — consent-based.
- *Initiating to a new contact* is blocked (=messenger-send-block-unknown=, t)
  until you approve it: =M-x messenger-allow-recipient= (adds the JID to
  =messenger-send-allowlist=), or interactively =M-x messenger-send-to-name=
  (resolves the name, confirms, approves, sends).
- *Rate limited:* =messenger-send-min-interval= (2s) and
  =messenger-send-max-per-hour= (30) cap bursts — keep it human-paced.

So an agent that wants to "message Max to organize dinner" must get your
approval first (you run the confirm command, or pre-approve Max's JID). Keep it
to a few real contacts who know you; do not bulk-message. Persist your own
"coach" reply JID in =messenger-send-allowlist= (personal value, set it in your
own init — not in this shared module) so replies survive restarts.

* Signal channel (signal-bridge-adapter)

Signal runs alongside WhatsApp on the SAME bridge — channel-routed: each adapter
only handles messages whose =channel= matches (=signal= / =whatsapp=), so the
agent sees a unified inbox and replies with =(messenger-send CHAT TEXT "signal")=
or ="whatsapp"=. Signal tolerates third-party clients far more than WhatsApp
(signal-cli is widely used), so ban risk is low.

Adapter: [[https://github.com/deno1011/signal-bridge-adapter][signal-bridge-adapter]] (Node + signal-cli), a separate process linked as a
SECONDARY device of your existing Signal account — no new number.

** One-time setup

#+begin_example
brew install signal-cli
git clone https://github.com/deno1011/signal-bridge-adapter.git ~/signal-bridge-adapter
cd ~/signal-bridge-adapter && npm install
cp .env.example .env          # set MESSENGER_BRIDGE_DIR (SAME as WhatsApp) + SIGNAL_ACCOUNT
#+end_example

Then, inside Emacs (these handle the keg-only-node PATH for you, so prefer them
over a raw terminal):

- =M-x my/signal-adapter-link= — renders the device-link QR in a buffer; scan
  it in Signal ▸ Settings ▸ Linked Devices ▸ Link New Device. Then set
  =SIGNAL_ACCOUNT= in =.env=.
- =M-x my/signal-adapter-install-service= — writes + loads the launchd service
  (fills the node path + dir automatically); =M-x my/signal-adapter-uninstall-service=
  to remove. Start it once from a terminal (=npm start=) to discover and

** Sending on Signal vs WhatsApp

#+begin_example
(messenger-send "+4915123456789" "Hi via Signal"   "signal")
(messenger-send "4915123456789@s.whatsapp.net" "Hi via WhatsApp" "whatsapp")
#+end_example

Same guardrails (approval + rate limit) apply to both. The =chat= form differs
per channel: Signal = =+E.164= number; WhatsApp = a =@s.whatsapp.net=/=@lid= JID.

* Connecting a DIFFERENT channel (not WhatsApp)

The bridge is channel-agnostic: WhatsApp is just one adapter. ANY process that
speaks the file protocol is a channel — Telegram, Signal, SMS, a web form, etc.
To add one, run an adapter (any language) that:

1. Reads =MESSENGER_BRIDGE_DIR= = `messenger-bridge-directory' (same path).
2. *Inbound:* on an incoming message, atomically write a JSON file into
   =inbox/= (write =.<name>.tmp= then rename to =<name>.json=) with the schema
   =({id, channel, chat, text, timestamp (ISO-8601 UTC), meta})=. Emacs picks
   it up and runs `messenger-on-message-functions'.
3. *Outbound:* poll =outbox/=; for each =*.json=, deliver =text= to =chat= on
   your channel, then move the file to =sent/=.

Set the message's =channel= field (e.g. "telegram") and use it when replying:
=(messenger-send CHAT TEXT "telegram")=. Multiple adapters can run at once
against the same bridge — each owns its =channel= name and its own =chat= ids.
The mock adapter (=adapters/mock_adapter.py= in the bridge repo) is the minimal
reference implementation to copy. Nothing in Emacs changes per channel; only a
new adapter process is added.

* Notes

- Recurring/self-chat echo and a dead file-notify watch are handled
  (echo-id skip in the adapter; poll self-heal in the bridge), so the channel
  stays reliable for long-running use.
- Doctor (=M-x my/doctor=) reports whether the bridge is loaded + watching.
