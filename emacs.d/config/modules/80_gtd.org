Numeric prefix =80-= places this module after =40-org.org=, so the
user's GTD tweaks override Org defaults set there.

This module provides the public default GTD setup for new installs:
compact files, small TODO keyword set, capture templates, project
tagging, stuck-project views, and tag-based life/travel views.

* User Manual

The user-facing starter manual lives in [[file:../starter-data/org/gtd.org][starter-data/org/gtd.org]].
During a new install it is copied to =data/org/gtd.org= in the selected
data repo, where the user can extend it with their own system notes.

** Files

- =inbox.org= :: raw capture, brain dumps, and anything not clarified yet.
- =gtd.org= :: next actions, projects, waiting-for, someday/maybe,
  tickler items, review lists, and the in-file manual.
- =calendar.org= :: appointments, hard deadlines, and dated commitments.
- =archive.org= :: completed or cancelled items after archiving.

Reference material can live outside GTD, for example in a wiki or notes.
Only add another GTD file when it solves a real review problem.

** Full Workflow

Use this system as a loop, not as a place to park vague intentions:

1. Capture everything unfinished into =inbox.org= with =C-c c i=.
2. Clarify one inbox item at a time until the inbox is empty.
3. Organize clarified outcomes into the right trusted bucket.
4. Reflect daily and weekly so the lists stay current.
5. Engage from agenda views by context, time, energy, and priority.

The apparently empty top-level headings in the starter =gtd.org= are
intentional landing zones for capture and refile. They begin empty
because a new user's real system should contain real actions, not
installer sample tasks.

This module follows Karl Voit's project model: projects are ordinary
TODO headings marked with a local =:project:= tag, not a separate TODO
keyword. During migration, older structural projects are still detected
when a TODO heading has TODO children.

** TODO Keywords

#+begin_example
TODO       not yet ready or not yet selected as the next physical action
NEXT       the next visible action you can do
WAITING    delegated, blocked, or waiting for external input
DONE       completed
CANCELLED  intentionally dropped
#+end_example

Keep the keyword set small. Context, energy, area, person, and topic
belong in tags or properties, not in extra TODO keywords.

** Clarify And Organize

Process inbox items one at a time. Decide whether each item is
actionable before deciding where it lives:

- trash it when it is no longer useful;
- move it to reference when it may be useful but requires no action;
- move it to =Someday / Maybe= when it may matter later but is not a
  current commitment;
- move it to =calendar.org= when it must happen on a specific date or at
  a specific time;
- move it to =Waiting= when someone else owns the next move;
- move it to =Next Actions= when it is one visible physical action;
- move it to =Projects= when it needs more than one action to finish.

** Projects

A project is any outcome that needs more than one action. Mark project
headings with the local =:project:= tag. Child tasks inherit normal
topic and context tags, but =:project:= itself does not inherit, so
agenda project views stay clean.

Use =C-c g p= on a heading to mark it as a GTD project. The command adds
the =:project:= tag, creates an ID, sets recursive TODO cookie data, and
adds a progress cookie when missing. Use =C-u C-c g p= when you also
want to set or change =CATEGORY=.

#+begin_example
** TODO [/] Renew driving license :project:admin:
:PROPERTIES:
:CATEGORY: license
:COOKIE_DATA: todo recursive
:END:
*** NEXT Find required city-office documents :@computer:
*** TODO Book appointment :@computer:
*** WAITING Confirmation from city office
#+end_example

Every active project should have at least one =NEXT= child action. If it
does not, it appears in the stuck-project agenda view with =C-c a X=.

** Trusted Buckets

- =Next Actions= :: standalone =NEXT= actions that are ready to do.
  Project-specific next actions may also live as children of their
  project.
- =Projects= :: active outcomes that need more than one action. Each
  project should say what finished looks like and what the next visible
  action is.
- =Waiting= :: delegated, blocked, or external items where the next move
  is not yours.
- =Someday / Maybe= :: possible future actions, ideas, and projects that
  are not current commitments.
- =Tickler= :: reminders that should resurface later; hard dates belong
  in =calendar.org=.
- =Horizons= :: areas, goals, and life values reviewed at slower
  cadences.

** Subprojects And Dependencies

If a task grows, turn it into its own project and link it to the parent
instead of forcing everything into one large tree. Use normal Org ID
links for loose relationships. Use =org-edna= only for dependencies that
should block or trigger state changes automatically.

Basic linking commands:

#+begin_example
M-x org-id-get-create  ;; create or show the current heading ID
C-c l                  ;; store a link to the current heading
C-c C-l                ;; insert a stored link elsewhere
#+end_example

Backlink commands:

#+begin_example
C-c g s                ;; create a bidirectional org-super-links link
C-c g l                ;; store current heading for a later super link
C-c g i                ;; insert the stored super link here
C-c g d                ;; delete a super link and its backlink
#+end_example

=org-super-links= is used only for backlinks. It is pinned to
=toshism/org-super-links= commit
=ce53993edc0fcfb85289f3eea74d1caa4dce8b60=. =org-linker-edna= is not a
core dependency because the dependency workflow stays small: ID links
for related items, =org-super-links= for backlinks, and =org-edna= for
real automatic blockers/triggers.

Dependency editing command:

#+begin_example
C-c g e                ;; edit org-edna BLOCKER/TRIGGER for this heading
M-x my/org-edna-edit   ;; same command by name
#+end_example

Inside the Edna edit buffer, write only the value below the =BLOCKER= or
=TRIGGER= section header. Finish with =C-c C-c=. Completion is available
with =M-TAB= or the normal completion key.

Example dependency properties:

#+begin_example
:BLOCKER: ids("id:parent-project-id")
:TRIGGER: ids("id:child-action-id") todo!(NEXT)
#+end_example

In practice, replace the example strings with real IDs. Put =BLOCKER=
on the heading that must not be completed until the referenced item is
ready. Put =TRIGGER= on the heading whose completion should change
another item, for example promote a child action to =NEXT=.

** Capture, Review, And Agenda

Use =C-c c= for capture templates. The compact GTD templates are:

- =i= :: inbox item
- =n= :: next action in =gtd.org=
- =p= :: project in =gtd.org=
- =w= :: waiting item
- =s= :: someday/maybe item
- =c= :: calendar item
- =f= :: flight/travel item

Daily review: empty =inbox.org=, check =calendar.org=, and choose a
realistic set of =NEXT= actions. Also glance at =Waiting= for follow-up
prompts.

Weekly review: inspect every =:project:= heading, make sure each active
project has a =NEXT= child, then review =WAITING=, =Someday / Maybe=,
Tickler items, areas, goals, and life horizons. Archive =DONE= and
=CANCELLED= items that no longer need to stay visible.

Monthly or quarterly review: inspect areas, goals, and life values;
create or retire projects accordingly.

Use =C-c a= for agenda views:

- =g= :: GTD dashboard
- =r= :: weekly review
- =J= :: all active projects
- =X= :: stuck projects without a =NEXT= child
- =B= :: blocked and waiting items
- =H= :: =@home= next actions
- =C= :: =@computer= next actions
- =E= :: =@errand= next actions
- =K= :: =@calls= next actions
- =A= :: areas
- =G= :: goals
- =L= :: life and values
- =R= :: higher-horizon review
- =f= :: flights and travel

* Project Helpers

#+begin_src emacs-lisp :tangle yes
(defvar my/org-project-structural-fallback t
  "When non-nil, treat old TODO headings with TODO children as projects.
Explicit local :project: tags remain authoritative.  The structural
fallback keeps older Org data visible during migration.")

(defun my/org-local-tags ()
  "Return local tags on the current Org heading."
  (org-get-tags nil t))

(defun my/org-heading-has-todo-child-p ()
  "Return non-nil when the current heading has a TODO-keyword child."
  (let ((end (save-excursion (org-end-of-subtree t t)))
        (found nil))
    (save-excursion
      (forward-line 1)
      (while (and (not found)
                  (re-search-forward org-heading-regexp end t))
        (when (member (org-get-todo-state) org-todo-keywords-1)
          (setq found t))))
    found))

(defun my/org-project-p ()
  "Return non-nil when the current heading is a GTD project.
Prefer an explicit local :project: tag.  Fall back to the older
structural project shape while user data is being migrated."
  (or (member "project" (my/org-local-tags))
      (and my/org-project-structural-fallback
           (member (org-get-todo-state) org-todo-keywords-1)
           (my/org-heading-has-todo-child-p))))

(defun my/org-heading-has-progress-cookie-p (title)
  "Return non-nil when TITLE already contains a progress cookie."
  (string-match-p "\\[[0-9]*/[0-9]*\\]\\|\\[[0-9]+%\\]" title))

(defun my/org-ensure-progress-cookie ()
  "Add a TODO progress cookie to the current heading when missing."
  (let ((title (nth 4 (org-heading-components))))
    (when (and title (not (my/org-heading-has-progress-cookie-p title)))
      (org-edit-headline (concat "[/] " title)))))

(defun my/org-project-has-next-p ()
  "Return non-nil when the current project has a NEXT child action."
  (let ((end (save-excursion (org-end-of-subtree t t)))
        (found nil))
    (save-excursion
      (forward-line 1)
      (while (and (not found)
                  (re-search-forward org-heading-regexp end t))
        (when (equal (org-get-todo-state) "NEXT")
          (setq found t))))
    found))

(defun my/org-skip-non-stuck-projects ()
  "Skip headings that are not stuck local GTD projects."
  (if (and (my/org-project-p) (not (my/org-project-has-next-p)))
      nil
    (save-excursion (org-end-of-subtree t t))))

(defun my/org-skip-non-projects ()
  "Skip headings that are not explicit or migration-fallback projects."
  (if (my/org-project-p)
      nil
    (save-excursion (org-end-of-subtree t t))))

(defun my/org-mark-as-project (&optional category)
  "Mark the current heading as a compact GTD project."
  (interactive
   (list (when current-prefix-arg
           (read-string "CATEGORY: " (or (org-entry-get (point) "CATEGORY") "")))))
  (unless (derived-mode-p 'org-mode)
    (user-error "This command works in Org buffers"))
  (unless buffer-file-name
    (user-error "Save this Org buffer before marking projects; IDs need a file"))
  (org-back-to-heading t)
  (unless (org-get-todo-state)
    (org-todo "TODO"))
  (org-toggle-tag "project" 'on)
  (org-entry-put (point) "COOKIE_DATA" "todo recursive")
  (when (and category (not (string= category "")))
    (org-entry-put (point) "CATEGORY" category))
  (org-id-get-create)
  (my/org-ensure-progress-cookie)
  (org-update-parent-todo-statistics)
  (message "Marked heading as GTD project"))

(global-set-key (kbd "C-c g p") #'my/org-mark-as-project)
#+end_src

* Legacy Overlay

The old private =data/org/gtd-config.el= overlay is intentionally not
loaded. GTD mechanics now live in this installer module so fresh
installs and existing machines use the same behavior.
